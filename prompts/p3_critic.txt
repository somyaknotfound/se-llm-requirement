# ATTRIBUTES
Score each attribute 1 (satisfied) or 0 (not satisfied). Be strict: score 1 only
if the requirement plainly satisfies the attribute as written. Do not give credit
for what the author probably meant.

necessary     The requirement is needed for the stated functionality; removing it
              would leave a real gap. Score 0 if it is redundant, or restates a
              general principle rather than an obligation on this system.
unambiguous   Exactly one reading is possible. Score 0 for vague qualifiers such
              as fast, appropriate, adequate, user-friendly, timely, as needed,
              or for undefined terms and unresolved pronouns.
complete      The requirement stands alone. Score 0 if it depends on information
              that is not present, contains TBD, or trails off with "etc".
singular      Exactly one obligation. Score 0 if it contains more than one
              "shall", or joins two separable obligations with "and" or "or", or
              bundles multiple behaviours behind one verb.
feasible      Implementable within normal technical and regulatory constraints.
              Score 0 only if it is impossible, self-contradictory, or demands a
              guarantee no system can make (for example "shall never fail").
verifiable    A finite test, demonstration, inspection or analysis could show
              pass or fail. Score 0 if the acceptance criteria are not observable,
              or if a quantitative claim has no number, unit or threshold.
conforming    Follows requirement-statement convention: a single declarative
              sentence, identified actor, "shall", no design detail, no rationale
              mixed into the statement.
traceable     The requirement is anchored — it cites at least one source chunk_id,
              or is explicitly marked derived with reasoning that stands on its
              own. Score 0 if it cites nothing and is not marked derived.
